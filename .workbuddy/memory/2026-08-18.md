## DirectoryOpus launcher 重大 bug 修复（用户反馈"换电脑要重新导入证书"）
- **根因（PAL 源码验证，不是猜测）**：拉取 GitHub `PortableApps/Launcher` 源码（`Other/Source/Segments/DirectoriesMove.nsh`），确认 PAL **只支持 `[DirectoriesMove]` 章节，`[Directories]` 章节根本不存在**（`grep ForEachINIPair` 全文只有 DirectoriesMove）。旧 launcher 里的 `[Directories]` 三行从未被 PAL 处理 → 三个 GPSoftware 目录（含存证书的 `%PROGRAMDATA%\GPSoftware`）从未搬进 Data → 换电脑必重新导入证书。
- **另一个 bug**：`[CloseEXE]` 也不是独立章节，而是 `[Launch]:CloseEXE` 单值选项（语义是启动前要求该进程未运行，与"退出时杀守护进程"相反）。旧配置 `[CloseEXE] EXE1=dopusd.exe` 同样无效。
- **修复**（`App/AppInfo/Launcher/DirectoryOpusPortable.ini`）：① `[Directories]`→`[DirectoriesMove]`（左侧唯一名=Data 子目录名，右侧=完整目标路径，与旧左侧名兼容）；② `%PROGRAMDATA%`→`%ALLUSERSAPPDATA%`（PAL 规范变量，Vista 后=C:\ProgramData）；③ 用 `[Launch]:RunAfter1="%WINDIR%\System32\taskkill.exe" /F /IM dopusd.exe` 在 DOpus 退出后杀守护进程释放文件锁（这才是 PAL 退出后清理的正确姿势，RunAfter 在 Post 搬目录前执行，源码 `RunBeforeAfter.nsh` + 主 nsi 顺序 PostExec→Post 确认）。
- **证书随身机制**（官方文档 + DOpus 论坛管理员证实）：DOpus 13 证书导入后授权状态= `%PROGRAMDATA%\GPSoftware\Directory Opus\dopus.cert`（删掉即回试用）。[DirectoriesMove] 生效后，dopus.cert 会随 ProgramDataGPSoftware 目录搬进 `Data\ProgramDataGPSoftware\Directory Opus\`，换电脑自动恢复 → **只需导入一次，永不重复导入**。也可直接把已激活机器的 dopus.cert 拷进 Data 对应位置跳过 License Manager（已写入 help.html）。
- 待用户：重新构建 launcher（install.py DirectoryOpus）→ 实测一次导入后 Data 是否长出 dopus.cert、换机是否自动激活。PROGRAMDATA 写入权限/是否需 RunAsAdmin 仍未实测。
